Goal: perform the package/binary/distribution rename from Rush to AUSH after an explicit compatibility strategy is chosen.

Current state: Cargo.toml still names package/lib/bin `rush`, binary output remains `target/.../rush`, Homebrew formula and CI release artifacts reference rush. This is intentionally deferred because it can break automation, shell paths, Homebrew installs, scripts, and tests.

Required decision before implementation:
- Decide whether Cargo package/lib stays `rush` internally during the migration or changes to `aush` now.
- Decide whether to keep a legacy `rush` binary/shim, symlink, or separate compatibility package.
- Decide Homebrew formula naming and release artifact names.

Steps after decision:
1. Update Cargo package/bin/lib names only according to the chosen strategy.
2. Add or preserve a legacy invocation path (`rush`) if that is the chosen compatibility mechanism.
3. Update Makefile, scripts, CI release workflow, Homebrew formula/readme, install docs, and smoke/bench invocations to prefer `aush`.
4. Keep a small targeted compatibility test proving the legacy invocation still works if retained.
5. Document migration guidance for existing `/etc/shells`, `chsh`, scripts, and dotfiles.

Likely files:
- Cargo.toml, Cargo.lock if needed
- Makefile
- .github/workflows/release.yml, .github/workflows/integration-tests.yml
- homebrew/Formula/rush.rb or new formula path depending on decision
- scripts/**, tests/smoke_test.sh, benches/** where binary path is relevant
- docs/INSTALLATION.md, docs/DISTRIBUTION.md

Out of scope:
- Deep internal Rust symbol rename unless required by Cargo rename
- Historical `.mana/**`, `research/**`, generated reports

Do not start implementation until the binary/package compatibility decision is recorded.
