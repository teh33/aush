## Task
Fix the live case parser in `src/parser/control_flow.rs` so the failing multiline `case` scripts in `tests/case_statement_tests.rs` parse and execute correctly.

## Root cause
The current `case` parser is too narrow in two places:
1. `parse_case_statement()` parses the case subject too much like a generic expression, which is fragile for shell-style words such as `$x` in multiline forms and plain hyphenated words like `test-file`.
2. `parse_case_pattern()` only accepts a single token, so valid shell patterns like `[abc]` and concatenated glob text like `test-*` are rejected.

## Required changes
1. Modify the live parser split module: `src/parser/control_flow.rs`.
2. Update `parse_case_statement()` so the word after `case` is parsed as a shell-style word up to `in`, while still producing an `Expression` that the existing executor can evaluate. It must support:
   - variable subject: `case $x in`
   - plain literal subject: `case foo in`
   - hyphenated literal subject: `case test-file in`
3. Update `parse_case_pattern()` so it can assemble a full pattern from consecutive tokens until a pattern separator (`|`) or arm terminator (`)`). It must handle at least:
   - bracket globs: `[abc]`
   - concatenated dash/glob patterns: `test-*`
   - existing simple patterns like `foo`, `*.txt`, `?`, `*`
4. Keep existing multiple-pattern handling (`foo|bar|baz`) intact.
5. Do not modify executor behavior for this unit.

## Files
- `src/parser/control_flow.rs` (modify)
- `tests/case_statement_tests.rs` (read for expected behavior; only modify if you must add or adjust a parser regression test in parser-specific tests)
- `src/parser/mod.rs` (read only unless the split module requires a mirrored regression test hook)

## Acceptance criteria
- `cargo test --test case_statement_tests` passes.
- No executor module changes.
- Existing simple `case` parsing behavior remains intact.
