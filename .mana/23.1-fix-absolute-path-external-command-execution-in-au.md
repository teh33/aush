AUSH fast smoke currently fails on absolute-path external command execution. Evidence from tests/smoke_test.sh:
- `/bin/true; echo $?` reports command not found instead of running successfully
- `/bin/false; echo $?` reports command not found instead of returning exit code 1

Goal:
- make absolute-path external commands execute correctly in the shell
- keep scope limited to command resolution/execution, not broader smoke-suite cleanup

Likely touch points:
- command resolution in executor command dispatch
- any builtin/external command discrimination that rejects names containing '/'

Verification:
- `tests/smoke_test.sh ./target/release/rush` should no longer fail the `/bin/true` and `/bin/false` cases
- at minimum, targeted manual checks with `./target/release/rush --no-rc -c '/bin/true; echo $?'` and `/bin/false; echo $?` should behave correctly
