## Task
Fix the live `while`/`until` parser in `src/parser/control_flow.rs` so shell-style conditional chains using `&&` / `||` parse as part of the loop condition/body instead of leaving dangling operator tokens.

## Root cause
`parse_while_loop()` and `parse_until_loop()` currently build their condition lists and body statements with `parse_statement()`. That loses shell conditional chaining. When the parser reaches `&& break`, `&& continue`, or `cond1 && cond2` inside a loop condition, the left command is parsed first and the next loop iteration sees `&&` as the start of a new statement, which leads to `Expected command name`.

## Required changes
1. Modify the live parser split module: `src/parser/control_flow.rs`.
2. In both `parse_while_loop()` and `parse_until_loop()`, parse loop condition entries with `parse_conditional_statement()` instead of `parse_statement()`.
3. Parse loop body statements with `parse_conditional_statement()` as well, matching the existing handling already used in `if` blocks and `case` bodies.
4. Preserve current newline/semicolon handling and `do`/`done` boundaries.
5. Do not change executor logic in this unit.

## Files
- `src/parser/control_flow.rs` (modify)
- `tests/while_loop_tests.rs` (read for failing forms)
- `tests/until_loop_tests.rs` (read for failing forms)
