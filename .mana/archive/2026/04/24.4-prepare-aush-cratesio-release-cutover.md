Goal: make AUSH publishable to crates.io under the `aush` package name, while preserving legacy `rush` binary compatibility.

Current evidence: `cargo publish --dry-run --allow-dirty` on 2026-04-27 packages `rush v0.1.0` successfully, but warns `crate rush@0.1.0 already exists on crates.io index`. This means current Cargo package metadata cannot publish a new AUSH crate; package name must change to `aush` or a separate package must be introduced.

Concrete steps:
1. Decide whether this repo is ready to rename `[package] name = "rush"` to `"aush"` now. Keep `[lib] name = "rush"` and `[[bin]] name = "rush"` for compatibility unless separately decided.
2. If yes, update Cargo.toml package name/version metadata and inspect Cargo.lock churn.
3. Run `cargo package --list` and reduce package contents with `include`/`exclude` if generated reports, research, target-adjacent artifacts, or unrelated files are included.
4. Run `cargo publish --dry-run` and confirm it verifies as `aush`.
5. Update release docs to distinguish crates.io package name `aush` from legacy binary `rush`.

Out of scope: actually publishing to crates.io; that requires explicit user approval and credentials. Also out of scope: removing legacy `rush` binary or renaming internal Rust library imports.
