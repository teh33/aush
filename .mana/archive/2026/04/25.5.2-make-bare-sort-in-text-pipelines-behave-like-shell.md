While fixing compound-command pipeline parsing, `cargo test --test pipeline_tests` still failed at `test_pipeline_with_sort_complex` with `ParseIntError { kind: Empty }`. Also manual experiments showed `printf 'src/lib.rs\nsrc/main.rs\n' | sort | wc -l` under AUSH returns `3` where bash/zsh return `2`, likely because native structured `sort` converts text lines to rows and emits a header row before `wc`. This is a compatibility problem for agentic shell pipelines where `sort` should behave like text sort when used as a command.

Steps:
1. Reproduce `printf 'src/lib.rs\nsrc/main.rs\n' | sort | wc -l` under AUSH vs bash.
2. Inspect `src/parser/mod.rs::try_parse_structured_op` and `src/executor/structured_ops.rs` behavior.
3. Decide/fix boundary: bare `sort` in ordinary shell pipelines should dispatch to text sort builtin/external command, while structured sort should require explicit structured syntax or only apply when previous output is structured.
4. Verify `cargo test --test pipeline_tests test_pipeline_with_sort_complex` and an explicit `printf ... | sort | wc -l` smoke.

Scope: Do not change the compound pipeline parser fix. This is a separate sort/structured pipeline compatibility bug.
