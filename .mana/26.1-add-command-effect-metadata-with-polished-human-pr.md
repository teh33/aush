Goal: introduce the first slice of AUSH command metadata/effects infrastructure, with explicit separation between machine-stable effect IDs and polished terminal presentation.

Current state/evidence:
- README.md positions AUSH as AI-native with structured pipelines.
- src/value/mod.rs has typed Value/Table.
- src/executor/structured_ops.rs has structured operators.
- src/history/mod.rs stores command+timestamp only.
- src/ai/agent.rs has confirmation for shell/write/edit tools, but no formal effect metadata.
- User design constraint: terminal output must be pretty. Raw IDs like `delete_file` are okay for JSON/schema/debug, but interactive output should say things like `Delete files`, `Write files`, `Access the network`, with concise descriptions and contextual summaries.

Steps:
1. Add a small effects/metadata module, likely `src/effects.rs` or `src/command_metadata.rs`, defining:
   - machine-stable effect IDs such as `read_file`, `write_file`, `delete_file`, `network_access`, `spawn_process`, `modify_git_history`.
   - a risk enum (`Low`, `Medium`, `High`) if useful for presentation.
   - human presentation helpers: title-case label, short description, maybe color/severity mapping.
2. Add unit tests proving:
   - machine IDs serialize as snake_case strings.
   - human labels are polished (`Delete files`, not `delete_file`).
   - high-risk effects render a readable summary suitable for prompts.
3. Wire the module into `src/lib.rs`/`src/main.rs` only as needed. Do not yet gate execution or change command behavior.
4. Optionally expose a tiny internal helper for builtins to attach effects later, but avoid broad refactors.

Files:
- src/effects.rs or src/command_metadata.rs (add — effect IDs + presentation helpers)
- src/lib.rs (modify — export module if needed)
- tests or inline module tests (add — presentation/serialization coverage)

In scope:
- metadata model and pretty rendering primitives.
- tests for machine-vs-human formatting.

Out of scope:
- approval gates.
- receipts ledger.
- full command schema registry.
- changing builtin execution behavior.
- printing raw effect IDs in normal terminal UI.

Do not:
- expose enum Debug output to users.
- add a large dependency for formatting.
- touch more than necessary; this is the substrate slice.
