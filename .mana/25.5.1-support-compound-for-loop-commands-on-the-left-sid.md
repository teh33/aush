AUSH parser currently fails with `Expected command name` for a pipeline whose left-hand side is a compound `for` loop, e.g. `for f in src/*.rs; do echo "$f"; done | grep lib | sort`. This came up while building the agentic compatibility benchmark. The benchmark fixture was narrowed to a plain loop so the new gate can pass, but real POSIX/agentic compatibility should support compound commands in pipelines.

Steps:
1. Reproduce with: `tmp=$(mktemp -d); mkdir -p $tmp/src; touch $tmp/src/main.rs $tmp/src/lib.rs; (cd $tmp && /Users/asher/rush/target/release/aush --no-rc -c 'for f in src/*.rs; do echo "$f"; done | grep lib | sort')`.
2. Add a targeted parser/executor regression test for compound-loop pipeline.
3. Fix parser/executor so `for ... done | command` parses and pipes loop stdout into next stage.
4. Verify existing loop and pipeline tests still pass.

Scope: Do not alter benchmark expectations to hide this bug. This is separate from current benchmark-suite plumbing task.
