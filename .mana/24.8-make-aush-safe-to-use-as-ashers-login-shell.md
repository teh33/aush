Goal for after the full AUSH rebrand worktree is cleaned up and committed: make AUSH safe enough to use as Asher's login shell.

Context from 2026-04-27:
- User wants this as a goal after the current worktree/rebrand cleanup is complete.
- Current macOS login shell is `/bin/zsh`; `$SHELL` is `/bin/zsh`; `/etc/shells` has no AUSH/Rush entry. AUSH exists at `/Users/asher/.cargo/bin/aush`. Current session parent was an old `/Users/asher/bin/rush` process, but system login shell remains zsh.
- Do not switch login shell yet. AUSH still has open parser/executor/smoke/job-control concerns and should first pass a dedicated login-shell readiness gate.

Scope:
1. Keep zsh as rollback/default until all gates pass.
2. Verify release build `target/release/aush` can start interactive and non-interactive sessions without rc hangs.
3. Verify `~/.aushrc` and `~/.aush_profile` behavior separately, including missing-file cases and PATH preservation.
4. Run existing login-shell tests and add/repair tests if they are stale from the rebrand.
5. Run TTY/job-control/signal smoke tests that matter for a login shell: Ctrl-C, Ctrl-D/exit, foreground/background jobs, pipelines, terminal restoration, child process cleanup.
6. Document exact install/rollback commands: add AUSH path to `/etc/shells`, `chsh -s ...`, verify with a new terminal, rollback to `/bin/zsh` from another terminal.
7. Only after verification, ask for explicit approval before running any command that changes `/etc/shells` or `chsh`.

Out of scope for now: actually changing the login shell; broad benchmark-suite work, which user will continue with another agent.
