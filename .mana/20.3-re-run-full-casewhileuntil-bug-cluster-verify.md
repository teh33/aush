## Task
Repair the incorrect scripts in `tests/while_loop_tests.rs` that currently create non-terminating loops. This is a test bug, not an executor refactor.

## Root cause
Several tests append `.` to a variable that starts as `"0"` and then compare it against `"3"`, `".."`, or `"...."`. With normal shell semantics those conditions never become false, so the tests hang indefinitely.

## Required changes
1. Modify `tests/while_loop_tests.rs` only.
2. Rewrite the long-running scripts so they still test the same intended behavior, but terminate deterministically. Use one of these two approaches consistently:
   - start from an empty string and append dots, or
   - use numeric arithmetic / numeric comparisons.
3. Preserve the meaning of each test:
   - `test_basic_while_loop` should still prove the loop runs exactly 3 times
   - `test_nested_while_loops` should still prove nested iteration counts are correct
   - `test_while_loop_exit_code_propagation` should still assert the last command's exit status is preserved
   - `test_while_loop_multiline_condition` should still prove multiline shell conditions work
4. Do not change parser or executor code in this unit.

## Files
- `tests/while_loop_tests.rs` (modify)

## Acceptance criteria
- The listed tests terminate quickly and pass.
- Only the test file changes for this unit.
